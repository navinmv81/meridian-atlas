## Non-Negotiable Rules

- Vanilla JavaScript only — no frameworks, no bundler.
- Cloudflare Workers compatible only.
- Modular domain boundaries must remain intact — no imports between domain JS files (`ma-etf.js`, `ma-entities.js`, `ma-13f.js`, etc. stay independent).
- Shared D1 free-tier discipline remains in force: 100k writes/day, 5M reads/day, 5GB storage. These are soft caps — over-cap writes are accepted without data loss, but must still be respected.
- Any new cron trigger requires the three-point check before activation. **Also note (added 2026-08-17): the Cloudflare Workers Free plan caps Cron Triggers at 5/account, separately from the 100/account Worker-script limit. The account was found at exactly 5/5 active as of 2026-08-17 — see MA-SEP-003's Change Request for the fix in progress. Check current utilization before assuming a new cron has room.** **Note (added 2026-08-21): this constraint is confirmed permanent — the Founder is staying on Cloudflare Workers Free plan as an explicit project premise, not a temporary/reversible choice. Do not propose a Paid-plan upgrade as a solution to any future limit; design within Free-tier limits instead.**
- Frontend and Worker deploys are separate mechanisms with no automatic link. Pushing to GitHub does not deploy a Worker. Running `wrangler deploy` does not update GitHub Pages. Both must be tracked explicitly.
- No environment, branch, folder, or schema change proceeds without `/change-request` producing an impact analysis and rollback plan first.
- **Recurring/automated components stay inside Cloudflare (Worker + D1 + Cron Trigger) — added 2026-08-21, Founder's explicit architectural preference.** A recurring job with no viable in-Cloudflare path (confirmed by real diagnostic numbers, not assumed) may run as a local scheduled job on the Founder's own machine instead (macOS LaunchAgent, precedented by MA-AUG-003 and now MA-SEP-003) — but any such local recurring job must ship with an explicit install / pause+resume / hard-stop("kill switch") / status control surface as a Founder-required acceptance criterion, not an optional nicety. Do not propose moving a recurring component to a third-party CI/scheduling service (e.g. GitHub Actions) — set aside 2026-08-21 per Founder preference to keep the architecture inside Cloudflare-or-local-machine only.
